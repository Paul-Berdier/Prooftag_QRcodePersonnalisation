# E014E — protocole d'ablation mécanistique et temporelle

## Question

E014D a rendu toutes les sorties originales lisibles par les trois décodeurs, mais la recette fixe
0,30 n'a obtenu que 151/156 validations robustes et a perdu jusqu'à 1,339 point de
CLIP-aesthetic. E014E doit déterminer quelle composante produit le gain de lecture et laquelle
détruit l'image.

## Hypothèses

Quatre effets étaient confondus dans E014D :

1. la remise sous bruit puis la rediffusion guidée par DiffQRCoder ;
2. la fusion du canal latent 1 sur l'ensemble de l'image ;
3. la fusion du blueprint sous le masque des motifs fonctionnels ;
4. une fenêtre fixe de huit pas tardifs.

L'hypothèse principale est qu'une partie importante de la perte visuelle vient de la fusion
globale alpha 0,15 répétée à chaque pas. Une combinaison plus faible ou une fenêtre plus courte
pourrait conserver l'original 3/3 sans « re-QRiser » toute l'image.

## Phase A — screening des mécanismes

Contextes :

- `p2_medium` ;
- `p3_detailed`.

Fenêtre : quatre derniers pas du planning DDIM à quarante pas.

Recettes :

| Groupe | Recettes |
|---|---|
| Rediffusion | sans injection latente supplémentaire |
| Fusion globale | alpha 0,03 ; 0,06 ; 0,10 |
| Masque seul | force 0,05 ; 0,10 ; 0,15 |
| Combinaisons faibles | 0,03/0,05 ; 0,06/0,10 ; 0,10/0,15 |
| Référence | 0,15/0,15 |

La référence est automatiquement promue. Les deux meilleures autres recettes sont classées par :

1. nombre de contextes original 3/3 ;
2. nombre de contextes 39/39 ;
3. pire SSR ;
4. SSR moyen ;
5. CLIP-aesthetic ;
6. CLIPScore ;
7. modification absolue.

La promotion est une génération d'hypothèse, pas une validation.

## Phase B — fenêtre temporelle

Les trois recettes promues sont comparées sur les quatre contextes avec deux, quatre, six et huit
pas tardifs. `p1_simple` et `p4_complex`, absents du screening, constituent le holdout.

Une recette fixe franchit la porte logicielle si :

- les quatre contextes passent l'original 3/3 ;
- son SSR moyen dépasse celui du contrôle E014B ;
- aucune perte CLIP-aesthetic ne dépasse 0,75 ;
- aucune modification absolue ne dépasse 0,18.

Le statut production exige en plus 39/39 dans les quatre contextes, puis des essais physiques.

## Contrôles de validité

- pipeline fraîche pour chaque candidat ;
- latent source et bruit identiques entre recettes d'un contexte ;
- latent initial identique entre recettes pour un même contexte et une même fenêtre ;
- suffixe exact du planning DDIM ;
- trois décodeurs et treize scénarios, soit 39 validations ;
- payload exact ;
- aucune correction de pixels après diffusion ;
- nettoyage automatique d'un candidat interrompu ;
- reprise seulement à partir d'artefacts complets et indexés ;
- journal `errors.jsonl` ;
- révisions de modèles et hash de DiffQRCoder dans le manifeste.

## Limite

Même en cas de succès, quatre prompts et une graine par prompt ne permettent pas d'entraîner un
sélecteur contextuel. La meilleure recette devra être confirmée sur des prompts, graines,
payloads, versions QR et appareils inconnus.
